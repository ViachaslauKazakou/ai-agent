# Этап 0. Подготовка проекта

## Цель

Подготовить минимальную и компилируемую основу Rust-проекта перед началом
реализации функциональности агента.

На этом этапе мы не реализуем CLI, подключение к LLM, сессии или tools.
Сначала нужно получить чистую точку старта, чтобы ошибки следующих этапов
были связаны с новым кодом, а не с незавершённым шаблоном.

## Исходное состояние

В исходном `src/main.rs` находились:

- демонстрационный вывод `Hello, world!`;
- учебный цикл печати чисел;
- незавершённый trait `LlmProvider`;
- ссылка на несуществующие типы `CompletionRequest` и `CompletionResponse`;
- атрибут `#[async_trait]` без корректного использования.

Из-за этого исходный проект не проходил `cargo check`.

## Что реализовано

### 1. Чистая точка входа

`src/main.rs` теперь содержит только минимальную функцию `main`, которая
печатает сообщение о готовности проекта к следующему этапу.

Это сознательное упрощение. На этапе 0 мы не пытаемся заранее реализовать
часть LLM API: сначала будут изучены модули, структуры и ошибки, а затем эти
типы появятся в предназначенных для них файлах.

### 2. Документация модуля

В начале `main.rs` добавлен комментарий `//!`. Такой комментарий описывает
назначение всего модуля и объясняет, почему текущая реализация минимальна.

### 3. Комментарий функции

Функция `main` снабжена Rustdoc-комментарием `///`. Для публичных API на
следующих этапах такие комментарии должны описывать назначение, ошибки,
ограничения и важные инварианты.

## Что изучаем в Rust

- структуру Cargo-проекта;
- роль файла `src/main.rs`;
- функцию `fn main()` как точку входа бинарного приложения;
- разницу между обычным комментарием `//`, документацией функции `///` и
  документацией модуля `//!`;
- базовый цикл проверки проекта через Cargo;
- значение ошибки компилятора как части рабочего процесса Rust.

## Почему незавершённый trait удалён

Trait `LlmProvider` относится к будущему этапу HTTP и абстракций provider.
Оставлять его в `main.rs` было неправильно по двум причинам:

1. Он ссылался на типы, которые ещё не спроектированы.
2. Он смешивал будущую бизнес-логику с точкой входа приложения.

На следующих этапах trait будет размещён в модуле `llm`, рядом с типами
запросов и ответов. Это позволит отделить запуск приложения от контракта
LLM-провайдера.

## Команды проверки

Все команды нужно выполнять из каталога проекта:

```bash
cd /Users/Viachaslau_Kazakou/Work/ai-agent/ai-agent
```

### Форматирование

```bash
cargo fmt -- --check
```

Проверяет, что исходный код соответствует стандартному форматированию Rust.

### Проверка компиляции

```bash
cargo check
```

Проверяет код без создания финального release-бинарника. Это быстрый способ
обнаружить синтаксические ошибки, неправильные типы и незавершённые ссылки.

### Тесты

```bash
cargo test
```

На этапе 0 отдельных тестов ещё нет, но команда должна успешно выполниться.

### Clippy

```bash
cargo clippy --all-targets --all-features -- -D warnings
```

Clippy рассматривает предупреждения как ошибки. Это помогает не накапливать
проблемы качества по мере роста проекта.

### Запуск

```bash
cargo run
```

Ожидаемый вывод:

```text
ai-agent: проект подготовлен к реализации этапа 1
```
