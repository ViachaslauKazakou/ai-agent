# Desktop Coder: file edits with per-diff approval

Coder открывается из launcher после выбора проекта. Проводник отображает до 400 записей (глубина до 5), пропуская symlink, `.git`, `.aiagent`, `.venv`, `node_modules`, `target` и имена, похожие на секреты. Для обхода используются directory handles; это не OS-песочница и **не** сканер секретов: обычные файлы и Git diff могут содержать секретные данные; не открывайте недоверенные проекты.

Git-изменения (`--porcelain=v1 -z --no-renames`) и diff конкретного изменённого tracked-файла доступны **только** если выбранный каталог — корень репозитория с локальным каталогом `.git`; подкаталог репозитория и linked worktree отклоняются. Доступны staged и unstaged diff tracked-файлов. Для untracked файлов diff не предоставляется. Максимум 400 изменений, 64 KiB вывода status/check, 32 KiB diff, 5 секунд на Git. Пути с traversal, чувствительными компонентами и symlink не принимаются. Вывод ошибки Git не отправляется в WebView. Кнопка «Check whitespace» запускает только `git diff --check`, не запускает сборку/тесты или код проекта и не проверяет untracked файлы. В каталоге без Git дерево и статус `.venv` доступны независимо, Git-контролы выключены.

Coder позволяет выбрать проектный профиль и файл внутри корня проекта, затем описать изменение. Содержимое выбранного файла отправляется на endpoint модели, настроенный для этого профиля; не выбирайте файлы с секретами или конфиденциальными данными. Backend читает один обычный UTF-8 файл (максимум 32 KiB) и просит профиль предложить одну уникальную буквальную замену. WebView показывает только текстовый diff. До нажатия «Apply this diff» файл не меняется; нажатие передаёт только opaque proposal ID, а backend применяет сохранённый сервером preview и создаёт checkpoint. Предложение одноразовое, привязано к проекту, профилю, относительному пути и исходному/new digest. Отклонение, смена проекта или профиля потребляет предложение. `can_write` означает только, что эта узкая approval-bound функция поддерживается платформой; он не включает произвольные profile write tools.

Только существующие файлы: создание новых файлов и удаление пока не включены. Shell, `run_command`, проектные build/test, pip, создание/исполнение venv и Git mutation (commit/push/PR/branch) недоступны. Profile write settings и allowlists не дают дополнительных прав. Профильные system prompt и skills используются только на стороне Rust и не отправляются в UI. Содержимое целевого файла рассматривается как недоверенные данные. Desktop Coder не записывает историю запроса/файла в Chat session.

Запись поддерживается пока только на Unix, поскольку `coder::apply_edit` отклоняет Windows. Backend повторно проверяет digest, ordinary-file/link constraints и checkpoint перед заменой; операция не является OS sandbox и не может полностью синхронизироваться с независимыми процессами, которые одновременно меняют проект (TOCTOU). Используйте только в доверенных проектах. Checkpoint содержит предыдущие байты и служит сохранённой копией; универсальный rollback не предоставляется. Ошибки/отказы могут оставить неиспользуемый checkpoint, но не должны менять целевой файл.

## Проверка

```bash
cargo fmt --all -- --check
cargo check --workspace
cargo test --workspace
cargo clippy --workspace --all-targets --all-features -- -D warnings
npm --prefix frontend run check
npm --prefix frontend run build
```

Manual smoke (Unix): выбрать профиль, указать существующий файл проекта и задачу; убедиться, что diff показан до изменений на диске. Reject должен закрыть предложение и оставить файл прежним. Повторить, нажать Apply this diff и проверить обновлённый файл и checkpoint. Попробовать traversal, `.env`, symlink и файл >32 KiB — backend должен отказать; выполнить shell/build/test нельзя. На Windows Coder остаётся только для read-only инспекции. Не использовать для секретных или недоверенных репозиториев.
