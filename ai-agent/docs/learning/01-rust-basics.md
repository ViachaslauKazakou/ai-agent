# Этап 1. Минимальная программа и базовый Rust

## Цель

Познакомиться с базовыми конструкциями Rust на маленькой полностью
работающей программе. До добавления CLI, HTTP и LLM нужно научиться
разделять ввод, преобразование данных и вывод результата.

Программа этапа принимает одну строку из stdin, разбирает её на слова и
показывает:

- общее количество слов;
- количество уникальных слов;
- первое слово, если ввод не пустой.

## Практическая задача

Ввод:

```text
Rust делает владение понятным
```

Результат:

```text
Всего слов: 4
Уникальных слов: 4
Первое слово: Rust
```

Для пустого ввода программа не должна падать:

```text
Ввод пустой: нужно указать хотя бы одно слово.
```

## Изменённые файлы

### `src/main.rs`

Содержит:

- чтение строки из stdin;
- `parse_words` для преобразования текста в `Vec<String>`;

- `first_item<T>` с результатом `Option<&T>`;

## Теория Rust

### 1. `String` и `&str`

`String` — изменяемая строка, владеющая памятью. В программе переменная
`input: String` владеет буфером, заполненным методом `read_line`.

`&str` — заимствованное строковое представление. Функция `parse_words`
принимает `&str`, поэтому она может обработать строку без передачи владения:

```rust
fn parse_words(input: &str) -> Result<Vec<String>, &'static str>
```

Результат содержит `Vec<String>`, а не `Vec<&str>`. Это важно: ссылки на
части `input` были бы привязаны к времени жизни исходной строки. Создание
`String` через `to_owned` переносит данные в новый владеющий контейнер.

### 2. Ownership и borrowing

В `main` строка создаётся один раз:

```rust
let mut input = String::new();
```

Затем `&mut input` временно передаётся в `read_line`. Функция получает
изменяемое заимствование, но не становится владельцем строки.

Вызов `parse_words(&input)` передаёт неизменяемое заимствование. После
возврата функция больше не использует `input`, а результат владеет своими
`String`.

Для подсчёта используется `&[T]` — заимствованный срез. Поэтому функция
`count_items` может принимать массив или `Vec` без копирования и без
изменения исходной коллекции.

### 3. `Vec<T>`

`Vec<String>` — динамический список строк. Он создаётся итератором:

```rust
let words: Vec<String> = input
    .split_whitespace()
    .map(str::to_owned)
    .collect();
```

Здесь:

1. `split_whitespace` выдаёт последовательность `&str`;
2. `map` преобразует каждый `&str` в принадлежащий программе `String`;
3. `collect` собирает элементы в `Vec<String>`.

### 4. `Option<T>`

У пустого списка нет первого элемента. Поэтому `first_item` не возвращает
фиктивное значение и не вызывает panic, а возвращает enum:

- `Some(&T)`, если элемент есть;
- `None`, если список пуст.

В `main` оба варианта обрабатываются через `match`.

### 5. `Result<T, E>`

`parse_words` может успешно вернуть список или сообщить об ошибке:

- `Ok(Vec<String>)` — ввод содержит слова;
- `Err(&'static str)` — ввод пустой.

На следующем этапе ошибки будут вынесены в собственный enum `AppError`.
Пока строковой ошибки достаточно, потому что задача специально ограничена
одним простым видом неправильного ввода.

### 6. Generic-функция

```rust
fn count_items<T>(items: &[T]) -> usize
```

`T` означает любой тип. Функция не требует знать, что находится внутри
среза: ей достаточно свойства `len`. Тест с числами доказывает, что функция
не привязана только к словам.

### 7. `HashSet`

`HashSet<&str>` хранит уникальные ссылки на слова. Ссылки безопасны внутри
функции, потому что строки принадлежат `words`, а `words` живёт до конца
вызова `count_unique_words`.

## Разбор потока программы

1. `main` печатает приглашение.
2. `flush` гарантирует, что приглашение видно до ожидания ввода.
3. `read_line` записывает строку в принадлежащий `String`.
4. `parse_words` разбирает строку через `split_whitespace`.
5. Пустая строка превращается в `Err` и обрабатывается сообщением.
6. Непустая строка превращается в `Vec<String>`.
7. `count_items` считает все элементы.
8. `count_unique_words` считает уникальные элементы.
9. `first_item` возвращает `Option`.
10. `main` печатает результат.

## Почему логика вынесена в функции

Если поместить весь код в `main`, его будет трудно проверять. Чистые функции
не зависят от терминала и позволяют передавать строки напрямую из тестов.
Это первый шаг к архитектуре агента, где ввод пользователя, LLM и tools тоже
будут разделены по отдельным слоям.

## Тесты

В `src/main.rs` добавлены пять тестов:

1. разбор слов сохраняет порядок;
2. пустой ввод возвращает ошибку;
3. generic-счётчик работает с числами;
4. первый элемент непустого списка возвращается через `Some`;
5. повторяющиеся слова считаются один раз.

Тесты используют `unwrap()` только для случая, где тест заранее проверяет
успешный сценарий. В пользовательском коде `unwrap` не используется.
